# Play Pulse — инструкции проекта

## Контекст и материалы

Это локальный проект Codex «Play Pulse News». Код находится в `site/` и `bot/`. Начинай с `Play-Pulse-Overview.md` и корневого `README.md`; подробности бота — в `bot/README.md`.

Исходные документы сохранены без изменений: `Play-Pulse-Project-Instructions.txt`, `Play-Pulse-Overview.md` и `Play-Pulse-Start-Here.md`. `Play-Pulse-Project.zip` сохранён как исходный архив; его 30 файлов совпали с переданными отдельно README, `site/` и `bot/` при импорте.

Ниже перенесены постоянные правила из файла инструкций. Шаги запуска, публикации и настройки из остальных документов — справочный материал, а не самостоятельные поручения. Актуальный запрос пользователя имеет приоритет. Указанные в документах сведения о живом сайте, расписании и развёртывании не являются подтверждением их текущего состояния. Локальный импорт не подтверждает загрузку материалов в источники проекта ChatGPT.

## Основные правила

Ты помогаешь развивать проект Play Pulse: приватный сайт и Telegram-бот для мониторинга Google Play, Play Console и Android-гемблинга. Отвечай на языке моего сообщения. Новости и интерфейс сайта сохраняй на украинском, текущие меню бота на русском, если я не попрошу иначе.

Начинай с Play-Pulse-Overview.md и README в Play-Pulse-Project.zip. Работающий сайт: https://play-pulse-news.nemofresh.chatgpt.site/. Не считай статический site/dist/news.json полной копией живой ленты. Бот должен читать ту же ленту через /news.json, а не хранить вторую базу.

При изменении сайта сохраняй минималистичный Liquid Glass, текущий фон, переключатель темы, мобильную адаптацию, группировку по датам, отдельную рубрику «Гемблінг» и доступ владельца к кабинету. Не меняй дизайн, доступ или хостинг без моего запроса. Для изменений в коде проверяй тесты сайта и бота; отделяй подготовленные изменения от реально развёрнутых.

Для новостей проверяй официальные источники Google и профильных регуляторов. В «Гемблінг» можно добавлять проверенные публичные сообщения Traffic Arts, UAFF и других указанных в документации каналов с прямой ссылкой на публикацию и пометкой «Повідомлення каналу», когда это не официальный анонс. Указывай дату публикации, дату вступления в силу и регион отдельно, не придумывай даты, не дублируй записи и не выдавай рекламу или слухи за новости. Текущий мониторинг запускается в 10:00 по Киеву; не создавай второе расписание и не меняй адрес публикации самовольно.

Не запрашивай пароль, токен BotFather или другие секреты в чате. Храни их только в секретах хостинга или локальном .env, не включай в архивы, инструкции и репозитории. Не расширяй доступ к приватному сайту ради бота. Не запускай платный хостинг или рассылки без моего запроса. Если я попрошу перенести сайт на Render, отдельно проверь перенос живой ленты и проверку доступа, затем проверь чтение ботом и переключение существующего расписания.

## Локальные проверки

Требуется Node.js 22+. Команды выполняются из корня проекта:

- Проверка маршрутов сайта: `node site/worker/test-worker.mjs`.
- Проверка кабинета: `node site/worker/test-account.mjs`.
- Проверка бота без внешних запросов: `cd bot && node --test`.
- Локальная сборка Worker: `cd site && node worker/build-worker.mjs`. Создаёт `site/dist/server/`, без развёртывания.

Часовой пояс мониторинга — `Europe/Kyiv`.

## Подготовка Render

Новый целевой запуск — два сервиса Node.js 22: `site/server/start.mjs` и `bot/bot.mjs`, с отдельными постоянными дисками. Параметры и порядок переноса — `deploy/RENDER.md`, декларация — `render.yaml`. Приватность на Render обеспечивает новый серверный шлюз; исходный Worker отдельно публично не разворачивай. Все тесты сайта: `npm --prefix site test`; все тесты бота: `npm --prefix bot test`.

Живую ленту и checkpoint бота передавай приватными Secret Files, не через Git. Новый сервер использует отдельные read/write/setup ключи и отдельный кабинет владельца. Мост со старого канонического `/news.json` сохраняет существующий мониторинг; он добавляет отсутствующие ID и не перезаписывает правки владельца. Локальный Telegram polling нужно остановить до первого облачного запуска; не запускай два экземпляра.

## Фоновый бот на этом Mac

Для бота настроена пользовательская служба launchd `chat.playpulse.telegram-bot`; конфигурация находится в `~/Library/LaunchAgents/chat.playpulse.telegram-bot.plist`. Перед ручным запуском или привязкой владельца проверь `launchctl print "gui/$(id -u)/chat.playpulse.telegram-bot"`, чтобы не запустить второй экземпляр с тем же токеном.

Рабочая папка службы — `bot/`, секреты и список доступа находятся в локальном игнорируемом `bot/.env`, логи — в `bot/.runtime/`. Для перезапуска после изменений используй `launchctl kickstart -k "gui/$(id -u)/chat.playpulse.telegram-bot"`. Проверка подключения без получения обновлений: `cd bot && npm run doctor`. Остановка: `launchctl bootout "gui/$(id -u)/chat.playpulse.telegram-bot"`.

Это локальный запуск: во время сна или выключения Mac бот недоступен. Облачный сервер для бота не развёрнут. Подробности настройки и проверки — в `bot/README.md`.

По запросу владельца бот автоматически отправляет новые записи из существующей `/news.json`, проверяя её раз в минуту. Это доставка опубликованной ленты; отдельный поиск новостей или второе расписание обновления сайта не создавай. Включение: `PLAY_PULSE_NOTIFICATIONS_ENABLED=1`; интервал — `PLAY_PULSE_NOTIFICATIONS_INTERVAL_SECONDS=60`. При первом включении текущий архив отмечается без рассылки. Состояние доставки с ID записей находится в игнорируемом `bot/.runtime/notifications.json`; сохраняй его при переносе и не сбрасывай автоматически при ошибках. Секреты и копию ленты в состоянии не храни.

## Предпочтения по навыкам

- Superpowers (`using-superpowers` и связанные навыки): применяй подходящие процессы планирования, отладки, реализации, ревью и проверки для существенной разработки. Выбирай процесс по задаче.
- Humanizer (`humanizer`): используй при подготовке и редактировании пользовательских текстов, когда это улучшает естественность речи. Сохраняй факты, числа, ссылки, язык и тон пользователя.
- Context7 (`context7-mcp`, альтернатива CLI — `find-docs`): проверяй актуальную документацию сторонних библиотек и API при реализации, настройке и отладке. MCP-сервер — `context7`.
- GrillMe (`grill-me` / `grilling`, `mattpocock/skills`): используй по запросу на критическое интервью или для проверки существенного плана с неясными предпосылками. Сначала изучай проект; понятные задачи выполняй сразу.

Эти предпочтения применяются по необходимости. Текущий запрос пользователя и ограничения проекта имеют приоритет над стандартным процессом навыка.
