# Play Pulse на Cloudflare

Сайт і Telegram-бот використовують один публічний Cloudflare Worker, два внутрішні SQLite-backed Durable Objects та постійну базу D1. Сайт відкривається після входу власника. Бот приймає команди через `/telegram/webhook` і читає ту саму стрічку з D1.

Обчислення пароля виконує внутрішній Durable Object `PlayPulseAuth` через прив’язку `AUTH`. Він приймає лише `POST /api/account/setup`, `POST /api/account/login` і `POST /api/account/password` після перевірок у шлюзі. Публічної адреси для об’єкта немає. Стрічка, обліковий запис, сеанси та стан доставки залишаються в D1. Формат `HMAC-PEPPER-PBKDF2-SHA256-v1` зі 100 000 ітерацій не змінюється; повторне створення кабінету чи перенесення його даних для ввімкнення об’єкта не потрібне.

Telegram обробляє Durable Object `PlayPulseBot` через прив’язку `BOT`. Публічний Worker спочатку перевіряє адресу, метод і секрет webhook, а потім передає запит об’єкту. Плановий обробник викликає його внутрішній `POST /internal/telegram-delivery`, який виконує міст стрічки та доставку. Цей шлях не відкриває публічного маршруту запуску доставки.

Cron щохвилини переносить нові опубліковані записи з приватної стрічки Sites і доставляє сповіщення. За один виклик він обробляє до 10 нових записів джерела й надсилає до трьох повідомлень Telegram. Кожна новина має окреме повідомлення з повним викладом; завеликий текст ділиться на пронумеровані продовження. Коли видавець почне записувати новини безпосередньо в Cloudflare, міст можна вимкнути після перевірки нового шляху публікації.

## Доступ і зберігання

У `cloudflare/wrangler.jsonc` слід зберігати `assets.run_worker_first: true`, `html_handling: "none"` і `not_found_handling: "none"`. Застосунок перевіряє доступ перед видачею файлів. Публічні лише сторінка входу, її CSS і JS, логотип, декоративне тло `scene-5.webp`, `/api/runtime` та `/healthz`. `/telegram/webhook` приймає запити з окремим секретом Telegram. Статичний `site/dist/news.json` і каталог збірки `server/` виключено із завантаження assets.

Конфігурація містить дві прив’язки та дві послідовні міграції:

| Прив’язка | Клас | Стабільне ім’я екземпляра | Міграція |
| --- | --- | --- | --- |
| `AUTH` | `PlayPulseAuth` | `play-pulse-owner-auth-v1` | `auth-v1`, `new_sqlite_classes: ["PlayPulseAuth"]` |
| `BOT` | `PlayPulseBot` | `play-pulse-telegram-v1` | `bot-v1`, `new_sqlite_classes: ["PlayPulseBot"]` |

Саме SQLite-backed Durable Objects доступні на Workers Free. Обидва класи залишають дані в D1, не створюють власних SQL-таблиць чи окремого процесу long polling. Якщо потрібна прив’язка недоступна, операція повертає помилку без виконання важкого обробника в головному Worker. [Durable Objects Free](https://developers.cloudflare.com/durable-objects/platform/pricing/).

D1 зберігає JSON-об’єкти в таблиці `objects`:

| Ключ | Дані |
| --- | --- |
| `news/updates-v1.json` | Повна спільна стрічка |
| `account/admin-v1.json` | Новий кабінет власника |
| `account/sessions-v1.json` | Хеші сеансів |
| `account/rate-*.json` | Обмеження спроб входу |
| `telegram/notifications-v1.json` | Попередній стан особистої доставки: `version`, `owners`, дата початкової відмітки й ID новин |
| `telegram/channel-notifications-v1.json` | Окремий стан каналу: `version`, `channels`, дата початкової відмітки й ID новин |
| `telegram/update-*-v1.json` | Оброблені Telegram updates |
| `telegram/notification-lease-*-v1.json` | Тимчасові блокування особистої доставки |
| `telegram/channel-notification-lease-*-v1.json` | Окремі тимчасові блокування доставки в канал |
| `telegram/notification-progress-*-v1.json` | Прогрес частин для конкретного одержувача й новини |
| `telegram/update-progress-*-v1.json` | Прогрес частин приватної картки новини |

Умовні записи порівнюють ETag в одному SQL-запиті. Пошкоджені дані спричиняють помилку; відсутня стрічка не замінюється порожнім архівом. Міст додає лише відсутні ID та зберігає редакції власника навіть за паралельного запису.

Прогрес частин містить лише `version`, `articleId`, відбиток повідомлення `fingerprint`, `parts` і `nextPart`. Підтверджена частина зберігається до наступної спроби; ID новини потрапляє в checkpoint після останньої частини. Якщо фінальний запис checkpoint тимчасово не вдався, вже підтверджені частини не надсилаються знову. Змінений виклад незавершеної новини має інший відбиток і починає доставку цієї редакції заново. Уже доставлені ID через правки автоматично не надсилаються знову. Тексти стрічки й секрети у стані доставки не зберігаються. Мережевий таймаут без відповіді Telegram залишає невизначеність: непідтверджений запит міг бути прийнятий і під час повтору інколи дає дублікат.

## Параметри Worker

Значення зберігаються в Cloudflare Secrets або локальних ігнорованих файлах із правами `0600`.

| Назва | Призначення |
| --- | --- |
| `PLAY_PULSE_PUBLIC_ORIGIN` | Точний HTTPS origin без кінцевого `/` |
| `PLAY_PULSE_OWNER_ID` | Постійний випадковий ідентифікатор нового кабінету |
| `PP_PASSWORD_PEPPER` | Окремий секрет із 64 шістнадцяткових символів |
| `PLAY_PULSE_READ_TOKEN` | Лише `GET` і `HEAD /news.json` |
| `PLAY_PULSE_WRITE_TOKEN` | Лише `POST /api/news` |
| `PLAY_PULSE_SETUP_TOKEN` | Початкове налаштування кабінету |
| `TELEGRAM_BOT_TOKEN` | Наявний токен бота |
| `TELEGRAM_ALLOWED_USER_IDS` | Дозволені числові ID через кому |
| `TELEGRAM_WEBHOOK_SECRET` | Перевірка заголовка `X-Telegram-Bot-Api-Secret-Token` |
| `PLAY_PULSE_NOTIFICATIONS_ENABLED` | `0` до перенесення стану доставки, потім `1` |
| `TELEGRAM_CHANNEL_ID` | Перевірений числовий ID приватного каналу з префіксом `-100`; не `@username` |
| `TELEGRAM_CHANNEL_BACKFILL` | Типово `0`; `1` дозволяє архівну доставку під час першої ініціалізації каналу |
| `TELEGRAM_OWNER_NOTIFICATIONS_ENABLED` | Типово `0`, коли канал налаштований, і `1` без каналу; `1` явно вмикає особисті копії |
| `PLAY_PULSE_UPSTREAM_SITES_TOKEN` | Сервісний доступ лише до поточного канонічного джерела Sites; потрібен тимчасово |

Ключі читання, запису й налаштування мають відрізнятися та містити від 32 до 128 символів base64url. `TELEGRAM_WEBHOOK_SECRET` допускає від 32 до 256 таких символів. Зберігайте ідентифікатор власника й pepper після створення кабінету: їх довільна заміна порушить перевірку наявного пароля.

## Увімкнення приватного каналу

Приватний канал Play Pulse створено в обліковому записі власника. Через Telegram API підтверджено тип `channel`, відсутність публічного username й статус `creator` для налаштованого власника. Бот має `can_post_messages: true` і неявне для адміністратора `can_manage_chat: true`. Інші перевірені додаткові права вимкнені, включно з `can_manage_direct_messages: false`, редагуванням і видаленням повідомлень, запрошеннями, призначенням адміністраторів, історіями та відеочатами. Приховане у формі право керувати особистими повідомленнями окремо вимкнено через офіційний інтерфейс власника й повторно перевірено через API.

Код підтримки каналу розгорнуто у версії `f77c6bc0`. Хмарну доставку налаштовано на архів із 41 новини: `TELEGRAM_CHANNEL_BACKFILL=1`, `TELEGRAM_OWNER_NOTIFICATIONS_ENABLED=0`. ID та ці прапорці передаються разом однією зміною секретів. Кожна новина вміщується в окреме повне повідомлення; хмарний Cron доставив усі 41 від старих до нових, до трьох за виклик. Завершення повторно перевірено 24.11.2026: checkpoint містить усі ID стрічки без повторів; особистий checkpoint залишився з 41 записом. Останні дописи перевірено в Telegram, повний текст 11 доступних карток збігся зі стрічкою. Сам факт розгортання для майбутніх змін не замінює перевірки фактичної публікації.

Перед першою ініціалізацією каналу виконайте налаштування в такому порядку:

1. Призупиніть автодоставку через `PLAY_PULSE_NOTIFICATIONS_ENABLED=0`.
2. Додайте бота адміністратором лише з правом «Публікувати повідомлення». Отримайте сталий числовий ID дозволеним способом. Збережіть `TELEGRAM_CHANNEL_ID`, обраний `TELEGRAM_CHANNEL_BACKFILL` і `TELEGRAM_OWNER_NOTIFICATIONS_ENABLED` разом, поки доставка вимкнена.
3. Перевірте доступ описаною нижче функцією без надсилання повідомлень.
4. Поверніть `PLAY_PULSE_NOTIFICATIONS_ENABLED=1` і перевірте чергу.

Не записуйте ID, приватне запрошення чи числові ID власників у документацію та Git. Якщо спочатку задати лише ID за активної доставки, наступний Cron може ініціалізувати канал без архіву до збереження `TELEGRAM_CHANNEL_BACKFILL=1`.

Експорт `verifyChannelAccess({env, fetchFn, signal})` із `cloudflare/telegram.mjs` виконує лише `getMe`, `getChat` і `getChatMember` та повертає `{id, title}`. Він перевіряє точний ID, тип `channel`, належність членства боту та право `can_post_messages: true` для адміністратора. Повідомлень ця перевірка не надсилає. Доставка також виконує цю перевірку перед першою ініціалізацією й перед надсиланням нових матеріалів.

За типового `TELEGRAM_CHANNEL_BACKFILL=0` поточний архів лише відмічається в новому checkpoint. Для нового порожнього каналу можна явно задати `TELEGRAM_CHANNEL_BACKFILL=1` до його першої ініціалізації. Після створення checkpoint зміна цього прапорця не скидає історію й не запускає повторний архів. Доставлені записи з нього автоматично не видаляються.

Канал отримує записи за полем `date` від старих до нових, за однакової дати за сталим ID. За один виклик надсилається до трьох повідомлень. Новина з продовженням починається, коли поточний виклик може вмістити всі її непідтверджені частини. Якщо є кілька одержувачів, початок черги обертається між хвилинами. Кожна новина перевіреної поточної стрічки з 41 запису вміщується в одне повне повідомлення.

Коли канал налаштований, особисті автосповіщення типово вимкнені. `TELEGRAM_OWNER_NOTIFICATIONS_ENABLED=1` додає їх для власників із дозволеного списку. Їхній checkpoint залишається окремим. Приватні команди завжди перевіряють список власників; у каналі немає кнопок із приватними callback-командами. Посилання на сайт зберігає його захист входом.

Після ввімкнення перевірте кількість доставлених ID і відсутність повторів за наступного виклику. Якщо Telegram повернув `429` або забрав право публікувати, черга залишається незавершеною. Пошкоджений checkpoint чи прогрес частин не скидайте: зупиніть доставку й розберіть причину.

## Оформлення та справжні медіа

24.11.2026 власник обрав лаконічний професійний стиль. Відредаговано title, summary і detail усіх 41 архівного запису зі збереженням решти полів; Sites і Cloudflare звірено після запису. Наявні повідомлення каналу змінено на місці. У 8 із них додано справжні обкладинки з джерел; 33 залишилися текстовими. У всіх caption збережено повний текст і джерела. Придатних відеофайлів у перевірених архівних матеріалах не знайдено.

Поточне повідомлення має заголовок, короткі абзаци повного викладу, компактні метадані та всі джерела у вигляді HTML-посилань. Клавіатури в каналі немає. Generic Telegram-прев’ю вимкнені: вони можуть показувати аватар, чужий заголовок або рекламний уривок замість ілюстрації. Приватні картки зберігають навігацію.

`cloudflare/media.mjs` читає лише дозволені публічні редакційні URL, надаючи перевагу офіційному блогу. Максимум два GET на новину, без переспрямувань, зі спільним таймаутом 4 секунди та лімітом HTML 128 КіБ. Запити не мають доступу до секретів чи cookie. Обкладинки й відео допускаються лише з перевірених шляхів Google/Android і Telegram CDN. Для Telegram потрібен медіаелемент усередині точного `data-post`; самого OG-аватара недостатньо.

Коли весь допис уміщується в caption до 1024 символів, він надсилається через `sendPhoto` або `sendVideo`. Для відео підтримується прямий MP4; непрозорий Telegram CDN URL без розширення допускається лише з перевіреного `<video>` у точному дописі. YouTube не завантажується як файл. Завеликий текст зберігається повністю в текстових повідомленнях до 4096 символів на частину. Підтверджена відмова Telegram 400 дозволяє текстову спробу; таймаут або некоректна відповідь лишають новину в черзі, щоб не створювати другий допис після невизначеної медіаспроби.

Для трьох новин resolver додає щонайбільше шість публічних GET до звичайного бюджету зовнішніх викликів; D1-запитів для медіа немає. Checkpoint, підтвердження частин і приватний доступ збережені. Живі фото перевірено редагуванням наявних повідомлень; нові планові `sendPhoto`/`sendVideo` покрито інтеграційними тестами. Нового планового допису з фото або відеокліпом після ввімкнення resolver ще не спостерігали.

Редакційні правила оновлено в чинному завданні Sites до першого запуску. Попередній дайджест «Новини Google Play і Play Console» залишився активним для особистого чату ChatGPT; запис на сайт у його інструкції вимкнено. Розклад обох наявних завдань не змінено, автоматичний видавець сайту один.

```sh

npm test

npx wrangler d1 create playpulsenews
```

`npm run build` виконує dry-run без публікації. Підставте отриманий `database_id` у прив’язку `DB`. Застосуйте схему:

```sh
npx wrangler d1 execute playpulsenews --remote --file schema.sql
```

Перед остаточним експортом зупиніть процес бота на Mac і збережіть його стан доставки. Отримайте повну живу стрічку через дозволений сервісний доступ. Початкова вибірка цього перенесення містить 41 запис; перевірте актуальний склад під час експорту. У локальному `site/dist/news.json` лише 12 початкових записів.

Із кореня проєкту підготуйте приватний імпорт:

```sh
node cloudflare/migrate.mjs \
  --news deploy/.private/live-news.json \
  --notifications deploy/.private/notifications.json \
  --out deploy/.private/cloudflare-import.sql
```

Утиліта створює новий SQL-файл із правами `0600` і виводить лише кількість записів та власників. Вона переносить повні новини й стан доставки, зберігаючи його поля. Старий кабінет Sites та його сеанси не імпортуються. Імпорт призначений для нової бази до ввімкнення сповіщень; повторне виконання не перезаписує наявні об’єкти.

Поверніться в `cloudflare/`:

```sh
npx wrangler d1 execute playpulsenews --remote --file ../deploy/.private/cloudflare-import.sql
npx wrangler deploy --secrets-file ../deploy/.private/cloudflare-secrets.json
```

Файл секретів містить параметри у форматі JSON і зберігається лише локально. Під час першого розгортання залиште сповіщення вимкненими. Оновлення секретів окремо від коду також підтримується:

```sh
npx wrangler secret bulk ../deploy/.private/cloudflare-secrets.json
```

Створіть новий кабінет запитом `POST /api/account/setup` із канонічним `Origin`, заголовком `X-Play-Pulse-Setup-Token` і JSON-полями `username`, `password`. Збережіть пароль локально або в менеджері паролів. Перевірте вхід, вихід і заборону читання `/news.json` без сеансу чи ключа.

Після звірки всіх ID та полів стрічки, стану доставки й перевірки кабінету ввімкніть сповіщення. Налаштуйте Telegram `setWebhook` на канонічний `/telegram/webhook`: `secret_token` із Worker Secrets, `max_connections: 1`, `allowed_updates: ["message", "callback_query"]`, `drop_pending_updates: false`. Long polling на Mac має залишатися зупиненим. Перевірте `/start`, `/news`, картку, джерело й архів. Для повернення до long polling спочатку вимикають webhook і зберігають актуальний стан доставки з D1.

## Безкоштовні ліміти й перевірка CPU

Workers Free обмежений 100 000 запитів на добу та 10 мс CPU на звичайний виклик. Приватні файли проходять через Worker і також створюють виклики. D1 Free включає 5 млн прочитаних і 100 000 записаних рядків на добу. Після вичерпання безкоштовних лімітів запити завершуються помилкою. Проєкт не вмикає платний план автоматично. [Ліміти Workers](https://developers.cloudflare.com/workers/platform/limits/), [D1 Free](https://developers.cloudflare.com/d1/platform/pricing/).

Для SQLite-backed Durable Object документація встановлює окремий типовий CPU-бюджет 30 секунд на виклик. Безкоштовний план включає 100 000 запитів до Durable Objects і 13 000 GB-s тривалості на добу. Обчислення пароля, обробка Telegram і планова доставка виконуються в цих компонентах. [Ліміти Durable Objects](https://developers.cloudflare.com/durable-objects/platform/limits/), [безкоштовні квоти](https://developers.cloudflare.com/durable-objects/platform/pricing/).

Після кожної зміни маршрутизації перевіряйте налаштування кабінету, вхід, зміну пароля, webhook і Cron через `wrangler tail` та Cloudflare Metrics/Workers Logs. Порівнюйте окремі події головного Worker, `PlayPulseAuth` і `PlayPulseBot`. Локальні тести та dry-run не замінюють вимірювання CPU на розгорнутому коді. [Вимірювання CPU](https://developers.cloudflare.com/workers/platform/limits/#cpu-time).
