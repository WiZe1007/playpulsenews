# Play Pulse · Telegram

[Відкрити @PlayPulseNewsBot](https://t.me/PlayPulseNewsBot)

Бот показує ту саму стрічку, що й приватний сайт Play Pulse: останні новини, сім категорій, окремий гемблінг, архів і картки з джерелами. Меню залишаються російською, новини українською. Кожна новина надсилається окремо з повними полями `summary` та `detail`.

## Поточний хмарний запуск

Бот працює через Cloudflare webhook і читає спільну стрічку з D1. Сайт: [Play Pulse](https://playpulsenews.play-pulse-cloudflare.workers.dev). Щохвилинний Cron переносить опубліковані новини з приватного Sites і запускає доставку; Mac для роботи не потрібен. Локальний LaunchAgent зупинено й вимкнено. Не запускайте long polling одночасно з активним webhook.

Хмарне завдання Sites для пошуку та публікації створено й перевірено: рівно одне ввімкнене завдання, щодня о 10:00 `Europe/Kyiv`. На момент створення його наступний запуск був призначений на 24.11.2026 о 10:00 за Києвом; фактичне виконання ще не спостерігали. Інструкція та метадані: [news-monitor-prompt.md](../deploy/news-monitor-prompt.md), [news-monitor.json](../deploy/news-monitor.json). Бот доставляє матеріал після появи у спільній стрічці.

Підтримку каналу й нового оформлення розгорнуто у версії `f77c6bc0`. Приватний канал Play Pulse створено в обліковому записі власника. Telegram API підтвердив тип `channel`, відсутність публічного username, відповідного власника та право бота публікувати повідомлення. Усі інші перевірені додаткові права, включно з керуванням особистими повідомленнями каналу, вимкнені; `can_manage_chat` є неявним правом адміністратора Telegram.

Хмарну доставку налаштовано на архів із 41 новини: `TELEGRAM_CHANNEL_BACKFILL=1`, `TELEGRAM_OWNER_NOTIFICATIONS_ENABLED=0`. ID каналу та обидва прапорці зберігаються разом, без проміжного ввімкнення лише ID. Хмарний Cron доставив усі 41 новину від старих до нових, до трьох повідомлень за виклик. Стан повторно перевірено 24.11.2026: усі ID присутні без повторів; попередній особистий checkpoint збережено. Останні дописи видно в Telegram, повний текст 11 доступних карток звірено зі стрічкою. Адресу приватного запрошення й числовий ID каналу в документації не зберігаємо.

## Команди й доступ

- `/start` та `/menu` відкривають головне меню.
- `/news` відкриває останні новини.
- «Категории» містить усі сім рубрик, включно з «Гемблинг».
- «Архив» показує записи від ранніх до пізніх.

Приватні команди доступні лише числовим ID із `TELEGRAM_ALLOWED_USER_IDS`. Групи, канал і сторонні особисті чати для команд ігноруються. Налаштування каналу не розширює доступ до приватного сайту або меню власника.

Картка окремої новини також показує повний виклад. Якщо він не вміщується в 4096 символів Telegram після обробки HTML, бот редагує перше повідомлення й надсилає пронумероване продовження. Кнопки джерел і навігація зберігаються.

## Автоматична доставка в Cloudflare

Параметри зберігаються у Worker Secrets. Повна конфігурація та перевірки доступу описані в [deploy/CLOUDFLARE.md](../deploy/CLOUDFLARE.md).

| Параметр | Поведінка |
| --- | --- |
| `PLAY_PULSE_NOTIFICATIONS_ENABLED` | `1` вмикає автоматичну доставку, `0` вимикає її; команди працюють далі |
| `TELEGRAM_CHANNEL_ID` | Перевірений сталий числовий ID приватного каналу з префіксом `-100`; `@username` не приймається |
| `TELEGRAM_CHANNEL_BACKFILL` | Типово `0`: наявний архів позначається без надсилання. `1` дозволяє доставку архіву для каналу, який ще не має checkpoint |
| `TELEGRAM_OWNER_NOTIFICATIONS_ENABLED` | Коли канал налаштований, типово `0`; `1` додатково надсилає новини дозволеним власникам. Без каналу особисті сповіщення типово ввімкнені |

Перед налаштуванням нового каналу призупиніть автодоставку через `PLAY_PULSE_NOTIFICATIONS_ENABLED=0`. Збережіть ID каналу, режим архіву й прапорець особистих копій разом, перевірте право публікувати й лише потім поверніть `PLAY_PULSE_NOTIFICATIONS_ENABLED=1`. Якщо спочатку ввімкнути канал із типовим режимом без архіву, щохвилинний запуск може встигнути позначити всі старі записи без надсилання.

Перед першою ініціалізацією каналу й перед надсиланням нових матеріалів бот перевіряє себе через `getMe`, точний канал через `getChat` і право публікувати через `getChatMember`. Для адміністратора потрібне `can_post_messages: true`. Достатньо права «Публікувати повідомлення»; додаткові адміністративні права для доставки не потрібні.

У канал новини надходять від старих до нових за датою публікації, а за однакової дати за сталим ID. Архів і щоденні добірки мають той самий порядок. Один виклик надсилає щонайбільше три повідомлення. Черга зберігається між викликами; якщо новина потребує двох частин, бот не починає її, коли для завершення бракує місця в поточному виклику. Кожна з 41 новини, перевірених на момент розгортання, вміщується в одне повне повідомлення.

Повідомлення містить рубрику, заголовок, дату публікації, статус за наявності, повний виклад і безпечні посилання на джерела. У каналі немає кнопок із приватними callback-командами. Кнопка сайту веде на захищену сторінку й не надає доступу без входу.

## Стан доставки й повторні спроби

Особисті сповіщення зберігають попередній checkpoint `telegram/notifications-v1.json`. Канал має окремий `telegram/channel-notifications-v1.json` та власне тимчасове блокування. У записах містяться лише дата початкової відмітки й ID доставлених новин. Увімкнення каналу не змінює історію особистих сповіщень.

Підтвердження продовжень зберігаються окремо: `articleId`, відбиток оформленого повідомлення, кількість частин і номер наступної частини. Після успішної відповіді Telegram номер зберігається; ID усієї новини додається до checkpoint лише після останньої частини. Якщо друга частина не надіслалася, повтор починається з неї. Якщо всі частини підтверджені, але фінальний checkpoint тимчасово недоступний, повтор завершує запис стану без нового повідомлення. Змінений виклад незавершеної новини має новий відбиток і починає доставку цієї редакції з першої частини. Уже доставлені ID через правки автоматично не надсилаються знову.

Стан не містить копії стрічки чи секретів. Пошкоджені записи зупиняють доставку та не скидаються автоматично. Зберігайте checkpoint і метадані частин під час перенесення. У разі `429` бот враховує `retry_after`; утрачене право публікувати залишає новини в черзі.

Після мережевого таймауту Telegram міг прийняти повідомлення, хоча підтвердження не надійшло. Повтор такої непідтвердженої спроби інколи може дати дублікат. Підтверджені й збережені частини повторно не надсилаються.

## Локальні перевірки

Потрібен Node.js 22+. Зовнішніх npm-залежностей у папці `bot/` немає. Із кореня проєкту:

```sh
npm --prefix bot test
npm --prefix cloudflare test
npm --prefix site test
```

Тести не звертаються до живого Telegram чи сайту. Wrangler dry-run: `npm --prefix cloudflare run build`.

## Резервний локальний режим

Наведені нижче кроки призначені для свідомого повернення до long polling. Перед ним перевірте стан webhook, зупиніть хмарну доставку й перенесіть актуальний checkpoint із D1. Інструменти проєкту не видаляють webhook автоматично. Для одного токена має працювати лише один спосіб отримання оновлень.

Усі команди цього розділу виконуються з `bot/`:

1. Скопіюйте `.env.example` в `.env`, якщо його ще немає, та виконайте `chmod 600 .env`. Заповніть `TELEGRAM_BOT_TOKEN` локально. Секрети не передавайте в чат і не зберігайте в Git.
2. Для чинного Cloudflare-сайту задайте `PLAY_PULSE_FEED_URL=https://playpulsenews.play-pulse-cloudflare.workers.dev/news.json`, `PLAY_PULSE_AUTH_MODE=bearer` та окремий ключ читання у `PLAY_PULSE_FEED_TOKEN`. Значення `sites` у старому прикладі стосується попереднього джерела Sites; його токен на інший хост не передавайте.
3. Виконайте `npm run setup` лише після погодженого перемикання webhook. Команда перевіряє токен і відсутність webhook, встановлює ім’я, опис, аватар та меню команд. Вона не отримує оновлень і не надсилає повідомлень.
4. Якщо список власників ще не налаштований, виконайте `npm run pair`, відкрийте видане посилання та натисніть «Запустить» у приватному чаті. Підтверджений числовий ID буде записаний у `TELEGRAM_ALLOWED_USER_IDS`. Потрібна команда з одноразовим кодом; звичайний сторонній `/start` доступу не дає. Наявний список не перезаписується.
5. Виконайте `npm run doctor`: він перевірить Telegram, відсутність webhook і читання живої стрічки.
6. Запустіть `npm start`.

Для кількох заздалегідь дозволених власників використовуйте числові ID через кому. `@username` не підходить. Прив’язку й звичайний процес запускайте послідовно. `setup`, `pair` і `doctor` відмовляться продовжувати за наявності webhook; це очікувано для поточного хмарного запуску.

Автосповіщення локального Node.js-бота налаштовуються так:

```dotenv
PLAY_PULSE_NOTIFICATIONS_ENABLED=1
PLAY_PULSE_NOTIFICATIONS_INTERVAL_SECONDS=60
```

Цей режим надсилає новини дозволеним приватним власникам; канал обслуговує поточна Cloudflare-реалізація. За першого ввімкнення локальний архів позначається без розсилки. Checkpoint міститься в `.runtime/notifications.json`, прогрес частин у `.runtime/notifications.json.progress.json`. Якщо задано власний шлях `PLAY_PULSE_NOTIFICATIONS_STATE_FILE`, файл прогресу утворюється додаванням `.progress.json`. Переносьте обидва файли разом.

## Фонова служба й альтернативний сервер

Поточний LaunchAgent `chat.playpulse.telegram-bot` вимкнений. Перед будь-яким ручним запуском перевіряйте:

```sh
launchctl print "gui/$(id -u)/chat.playpulse.telegram-bot"
```

Для локального запуску існує `macos-launchd.plist.example`. Секрети залишаються в `.env`; у plist записуються лише абсолютні шляхи. Після свідомого перемикання з webhook службу можна встановити так:

```sh
launchctl enable "gui/$(id -u)/chat.playpulse.telegram-bot"
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/chat.playpulse.telegram-bot.plist"
```

Зупинка служби:

```sh
launchctl bootout "gui/$(id -u)/chat.playpulse.telegram-bot"
```

Після змін локального коду або `.env` установлену службу перезапускають через `launchctl kickstart -k "gui/$(id -u)/chat.playpulse.telegram-bot"`. На Mac бот недоступний під час сну або вимкнення комп’ютера.

Альтернативний контейнерний запуск:

```sh
docker build -t play-pulse-telegram .
docker run -d --name play-pulse-telegram --restart unless-stopped --env-file .env -v play-pulse-state:/app/.runtime play-pulse-telegram
```

Публікувати порти не потрібно. Перед запуском контейнера зупиніть інший процес. Підготовлений варіант Render описаний у [deploy/RENDER.md](../deploy/RENDER.md); він не є чинним розгортанням. Платний сервіс потребує окремого дозволу користувача.

## Якщо змінюється адреса сайту

Бот читає ту саму `/news.json`; відповідь має надходити без перенаправлень. Для закритого стороннього сервера потрібні `PLAY_PULSE_AUTH_MODE=bearer` і окремий ключ лише для читання в `PLAY_PULSE_FEED_TOKEN`. Режим `sites` дозволений тільки для точного канонічного джерела Sites. Режим `none` підходить лише для навмисно публічної стрічки; поточна стрічка приватна.

Кнопка «Открыть Play Pulse» використовує хост стрічки; окрему HTTPS-адресу можна задати через `PLAY_PULSE_PRESENTATION_URL`. У локальному режимі після зміни виконайте `npm run doctor` та перезапустіть єдиний процес. Для Cloudflare перевірте канонічний origin, доступ до сайту, webhook і розгорнутий код.

Перенесення сайту включає повний живий архів, серверне сховище, доступ власника й чинне хмарне завдання о 10:00 `Europe/Kyiv`. Статичний `site/dist/news.json` повної стрічки не містить.

Формат запису: `id`, `date` (`YYYY-MM-DD` або `YYYY-MM`), `category`, `title`, `summary`, `source`. Додатково підтримуються `detail`, `status`, `sourceLabel` та масив `sources` із полями `label` і `url`. Поточні межі викладу: `summary` до 1400 символів і `detail` до 3600.
