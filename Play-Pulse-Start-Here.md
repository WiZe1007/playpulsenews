# Play Pulse: добавление в ChatGPT и запуск

## 1. Добавить в проект

1. В приложении переключись с **Codex** на **ChatGPT**. Открой «Проекты → Play Pulse» или [проект по ссылке](https://chatgpt.com/g/g-p-6b04442a747c8191b6a44113cd4858da/project).
2. Открой **Источники (Sources) → Добавить источники → Загрузить**. Добавь `Play-Pulse-Overview.md` и `Play-Pulse-Project.zip`, если их там ещё нет. На момент подготовки оба файла уже были добавлены через веб-версию. Для другого проекта можно загрузить те же два файла; дубли не нужны. В ZIP папки `site/` и `bot/` и README. Если интерфейс просит распаковать ZIP, начни с обзора и README, а архив используй для работы с файлами на компьютере.
3. Открой меню **⋯ → Настройки проекта (Project settings)**. Вставь весь текст из `Play-Pulse-Project-Instructions.txt` в поле инструкций и сохрани. Эта настройка задаёт контекст для новых чатов проекта, но не разворачивает сервисы и не создаёт расписание.
4. Для продолжения работы с кодом распакуй ZIP локально. Для первой задачи в проекте можно написать: «Прочитай обзор и README Play Pulse. Сначала проверь текущие файлы, затем предложи план изменений. Ничего не публикуй».

[Документация ChatGPT Projects](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)

## 2. Запустить бота после подготовки работающей ленты

1. В [@BotFather](https://t.me/BotFather) отправь `/newbot`, выбери имя и username, оканчивающийся на `bot`. Сохрани выданный токен в менеджере паролей или секретах хостинга. Открой личный чат нового бота и отправь `/start`; до запуска процесса ответа не будет.
2. Нужен числовой Telegram ID владельца, не @username. На Mac, в стандартном Terminal с Node.js 22+, выполни этот блок. Токен вводится скрыто; команда печатает только ID из личного чата. Запускай до включения бота на хостинге, когда другой процесс не опрашивает Telegram:

   ```sh
   printf 'Токен BotFather: '
   read -rs TG_TOKEN
   printf '\n'
   TG_TOKEN="$TG_TOKEN" node -e '
     (async () => {
       const r = await fetch("https://api.telegram.org/bot" +
         process.env.TG_TOKEN + "/getUpdates", {redirect: "error"});
       const j = await r.json();
       if (!j.ok) { console.log("Telegram не вернул обновления. Проверь токен и отсутствие второго процесса."); return; }
       const m = j.result.findLast(u => u.message?.chat?.type === "private")?.message;
       console.log(m?.from?.id ?? "Отправь /start в личном чате и повтори.");
     })().catch(() => console.log("Не удалось связаться с Telegram."));
   '
   unset TG_TOKEN
   ```

3. **Локально:** зайди в `bot/`, скопируй `.env.example` в `.env`, заполни переменные ниже и выполни `node --env-file=.env bot.mjs`. **На Render:** загрузи содержимое папки `bot/` в приватный репозиторий без `.env`, выбери **New → Background Worker**, репозиторий и режим **Docker**. Если `Dockerfile` в корне репозитория, поле Root Directory оставь пустым. Проверь цену перед созданием сервиса. В Render заполни Environment Variables вручную, не сохраняй реальные значения в Git.

   | Переменная | Значение |
   | --- | --- |
   | `TELEGRAM_BOT_TOKEN` | Токен BotFather |
   | `TELEGRAM_ALLOWED_USER_IDS` | Числовой Telegram ID владельца |
   | `PLAY_PULSE_FEED_URL` | Точный HTTPS-адрес `/news.json` без редиректа |
   | `PLAY_PULSE_AUTH_MODE` | `sites` для текущего приватного сайта при наличии разрешённого сервисного доступа; `bearer` для закрытой ленты на Render с отдельным ключом чтения; `none` только для намеренно открытой ленты |
   | `PLAY_PULSE_FEED_TOKEN` | Секрет чтения для выбранного режима; для `none` не нужен |

4. Запусти **один экземпляр** бота, отправь `/start` и проверь **Последние новости**, **Гемблинг**, **Архив** и ссылки карточек. Для проверки кода без внешних запросов выполни `node --test` в папке `bot/`. Бот отвечает по запросу и не рассылает новости автоматически.

[Telegram BotFather](https://core.telegram.org/bots/tutorial) · [Telegram getUpdates](https://core.telegram.org/bots/api#getupdates) · [Render Background Worker](https://render.com/docs/background-workers) · [Секреты Render](https://render.com/docs/configure-environment-variables)

## 3. Если переносишь сам сайт на Render

Текущий сайт использует приватный доступ ChatGPT Sites и серверное хранилище. Копирование сайта как статики поднимет внешний вид и первоначальную ленту, но не перенесёт кабинет, доступ владельца и живой архив. До переключения нужно перенести актуальную ленту, настроить хранение и доступ на новом сервере, проверить выдачу JSON и проверить запись новости. Затем поменять адрес у бота и **отдельно** перенастроить существующее обновление в 10:00 по Киеву. Не копируй секрет Sites в режим `bearer` на Render: используй новый ключ только для чтения. Бот и сайт на Render ещё не запущены в рамках этого проекта.
