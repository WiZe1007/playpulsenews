# Play Pulse · Telegram

[Открыть @PlayPulseNewsBot](https://t.me/PlayPulseNewsBot)

Закрытый бот показывает ту же ленту, что и сайт Play Pulse: последние новости, семь категорий, отдельный гемблинг, архив и карточки со ссылками на источники. Меню на русском, новости сохраняют язык сайта. По запросу владельца включены автоматические уведомления о новых записях.

Поточне хмарне розгортання використовує Cloudflare Free: webhook, спільну стрічку та стан доставки в D1. Підключений сайт: https://playpulsenews.play-pulse-cloudflare.workers.dev. Нові записи перевіряються раз на хвилину, Mac можна вимикати. Локальний LaunchAgent зупинено й вимкнено; одночасний long polling порушить роботу webhook. Порядок перенесення та секрети описані в [інструкції Cloudflare](../deploy/CLOUDFLARE.md).

## Настройка локального режима

Нужен Node.js 22+. Все команды ниже выполняются из папки `bot/`. Внешних npm-зависимостей нет.

1. Скопируйте `.env.example` в `.env`, если файл ещё не создан, и выполните `chmod 600 .env`. Заполните `TELEGRAM_BOT_TOKEN` и `PLAY_PULSE_FEED_TOKEN` локально. Секреты не передавайте в чат и не сохраняйте в Git.
2. Для текущего приватного сайта оставьте `PLAY_PULSE_FEED_URL=https://play-pulse-news.nemofresh.chatgpt.site/news.json` и `PLAY_PULSE_AUTH_MODE=sites`. Нужен существующий сервисный токен Sites для этого сайта, а не пароль кабинета или токен Telegram.
3. Выполните `npm run setup`. Команда проверит токен и отсутствие webhook, установит имя, описание, аватар и меню команд. Она не запускает получение сообщений.
4. Выполните `npm run pair`, откройте выданную ссылку и нажмите «Запустить» в личном чате с ботом. Подтверждённый числовой ID будет записан в `TELEGRAM_ALLOWED_USER_IDS`. Привязка принимает только команду с одноразовым кодом; обычный `/start` постороннего пользователя не даёт доступ. Уже настроенный список владельцев не перезаписывается.
5. Выполните `npm run doctor`. Проверка должна подтвердить Telegram, отсутствие webhook и чтение живой ленты.
6. Запустите `npm start`.

`.env` хранится локально с доступом только владельцу файла. Если ID уже известен, его можно записать в `TELEGRAM_ALLOWED_USER_IDS` вручную; для нескольких заранее одобренных пользователей используйте запятую. `@username` вместо числового ID не подходит.

Привязку и обычный процесс бота запускайте по очереди. Для одного токена должен работать один процесс long polling. Если обнаружен webhook, проверьте существующее подключение: инструменты проекта не удаляют его автоматически.

## Команды и проверки

- `/start` и `/menu` открывают главное меню.
- `/news` открывает последние новости.
- «Категории» содержит все семь рубрик, включая «Гемблинг».
- «Архив» показывает записи начиная с ранних.

После запуска отправьте `/start`, откройте последние новости, карточку, оригинальный источник, гемблинг и архив. Группы и личные чаты с ID вне списка доступа игнорируются.

`npm test` выполняет проверки без Telegram и живого сайта. Проверки всего проекта из корня:

```sh
node site/worker/test-worker.mjs
node site/worker/test-account.mjs
node --test bot/*.test.mjs
```

Бот учитывает задержку `retry_after` при ограничении Telegram и поддерживает остановку через SIGINT/SIGTERM. Ошибки выводятся без токенов и сырых ответов API. После сетевого таймаута отправки Telegram мог уже принять сообщение, поэтому повтор в редких случаях может дать дубликат ответа.

## Автоматические новости

В локальном `.env`:

```dotenv
PLAY_PULSE_NOTIFICATIONS_ENABLED=1
PLAY_PULSE_NOTIFICATIONS_INTERVAL_SECONDS=60
```

Бот раз в минуту читает существующую ленту `/news.json` и отправляет новые записи разрешённым владельцам. Новостной поиск и публикация на сайте остаются у существующего мониторинга. Время 10:00 в документации относится к запуску этого мониторинга; уведомление приходит после появления материала в ленте.

При первом включении бот отмечает текущий архив без рассылки. Дальше сравнивает стабильные ID новостей, поэтому поздно добавленный материал обнаружится даже с более ранней датой. После перезапуска или пробуждения Mac отправка продолжается с сохранённого состояния. Если новых записей нет, сообщения не отправляются.

Уведомления оформлены как дайджесты Play Pulse: дата выпуска, рубрики, заголовки, краткие описания, даты публикации, статусы и кнопки источников. Большой выпуск делится между новостями на несколько сообщений. Тексты новостей сохраняются на украинском; язык меню остаётся русским.

Файл `.runtime/notifications.json` хранит только служебное состояние и ID записей для каждого владельца. Копия новостной ленты и секреты туда не записываются. После подтверждённой отправки каждой части бот сохраняет её ID атомарно. Повреждённое состояние останавливает автоотправку; оно не сбрасывается автоматически. Сохраняйте этот файл при переезде и разбирайте ошибки до его удаления.

Для отключения задайте `PLAY_PULSE_NOTIFICATIONS_ENABLED=0` и перезапустите единственный процесс бота. Это отключает автоуведомления; команды и меню продолжают работать.

## Постоянный запуск

Обычный `npm start` работает, пока запущен процесс. Для работы после закрытия терминала используйте фоновую службу macOS или один постоянно работающий контейнер на сервере. На Mac бот недоступен во время сна и после выключения компьютера.

Для macOS есть `macos-launchd.plist.example`. Замените абсолютные пути к Node.js, папке бота и логам, создайте `bot/.runtime/`, затем сохраните конфигурацию как `~/Library/LaunchAgents/chat.playpulse.telegram-bot.plist`. Секреты остаются в `.env`; в plist записаны только пути. Перед установкой проверьте `npm run doctor`.

```sh
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/chat.playpulse.telegram-bot.plist"
launchctl print "gui/$(id -u)/chat.playpulse.telegram-bot"
```

Остановка и удаление службы из текущего сеанса:

```sh
launchctl bootout "gui/$(id -u)/chat.playpulse.telegram-bot"
```

Чтобы отключить запуск при следующем входе в macOS, уберите plist из `~/Library/LaunchAgents/`. После изменения кода или `.env` перезапустите установленную службу через `launchctl kickstart -k "gui/$(id -u)/chat.playpulse.telegram-bot"`.

Для Docker:

```sh
docker build -t play-pulse-telegram .
docker run -d --name play-pulse-telegram --restart unless-stopped --env-file .env -v play-pulse-state:/app/.runtime play-pulse-telegram
```

Порты публиковать не нужно. Перед запуском контейнера остановите локальный экземпляр. В Render подходит Background Worker с Dockerfile из этой папки; секреты задаются в Environment. Создание платного сервиса требует отдельного запроса пользователя.

## Если меняется адрес сайта

Бот читает `/news.json` напрямую и не хранит вторую базу. JSON должен быть доступен без перенаправлений.

- Для закрытой ленты на новом сервере укажите её URL, `PLAY_PULSE_AUTH_MODE=bearer` и отдельный секрет только для чтения в `PLAY_PULSE_FEED_TOKEN`.
- Для намеренно публичной ленты допустим `PLAY_PULSE_AUTH_MODE=none` без токена ленты.
- Режим `sites` отправляет токен только на точный канонический адрес текущего сайта. Не переносите токен Sites на другой хост.

Кнопка «Открыть Play Pulse» использует хост ленты; при необходимости задайте `PLAY_PULSE_PRESENTATION_URL` с HTTPS-адресом. После изменения выполните `npm run doctor` и перезапустите единственный процесс бота.

Перенос самого сайта требует отдельно перенести живой архив, серверное хранилище и проверку доступа владельца. Затем нужно переключить существующее ежедневное обновление в 10:00 `Europe/Kyiv`. Статический `site/dist/news.json` не содержит всей живой ленты.

Формат записи: `id`, `date` (YYYY-MM-DD или YYYY-MM), `category`, `title`, `summary`, `source`. Дополнительно поддерживаются `detail`, `status`, `sourceLabel` и массив `sources` с полями `label` и `url`.
